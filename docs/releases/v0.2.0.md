# Codex Scope v0.2.0

Conformance-backed compatibility release for the existing Codex diagnostic surface.

## What is new

- A checked-in corpus of 32 semantic rules and 4 regression/change records, each tied to explicit evidence and expected outcomes.
- A generated compatibility matrix plus `codex-scope compatibility` terminal and JSON output.
- An offline `--codex-version` input that records version context without invoking Codex or inferring compatibility.
- Machine-readable conformance validation that distinguishes behavior drift, expected unsupported/unresolved cases, and tool failures.
- A neutral static adapter seam for future evidence-gated agent support.

## Correctness fixes

- Align project trust, instruction discovery, and historical approval-policy behavior with the pinned Codex evidence snapshot.
- Preserve unresolved invocation state when a discovered legacy policy is unsupported.
- Carry report-level instruction uncertainty into neutral adapter records.
- Return valid `tool_error` JSON when conformance corpus metadata is missing or malformed.

## Compatibility

The existing `inspect`, `instructions`, `config`, and `why` commands retain their terminal behavior and `codex-scope.v0.1` JSON contract. The new compatibility command uses the additive `codex-scope.compatibility.v1` contract.

This release still models an explicitly documented subset of Codex. Unknown versions remain unknown, and runtime/task/model-dependent state remains conditional, unresolved, or unsupported rather than guessed.

## Safety

The deterministic path remains read-only and adds no LLM calls, runtime network access, subprocess execution, hook/plugin/MCP execution, or inspected-repository mutation.
