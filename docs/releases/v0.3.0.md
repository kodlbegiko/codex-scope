# Codex Scope v0.3.0

Gemini CLI conformance-adapter preview on top of the stable Codex diagnostic surface.

## What is new

- A pinned Gemini CLI evidence manifest with 27 deterministic research cases.
- A bounded, read-only Gemini adapter for the explicitly authorized subset.
- Three sanitized real-repository validations and three distinct external upstream evidence records.
- Machine-enforced validation for coverage, evidence honesty, fixture containment, implementation state, and semantic assertions.
- A combined corpus of 59 deterministic cases across Codex and Gemini CLI.

## Preview boundary

This release validates the shared adapter architecture; it does not add a public cross-agent comparison command. The existing `inspect`, `instructions`, `config`, `why`, and `compatibility` commands remain Codex-facing.

The Gemini subset covers pinned facts such as context filenames and hierarchy, settings precedence, explicit trust provenance, explicit-target JIT candidates, inert extension activation snapshots, MCP declarations, and conservative import detection. Runtime discovery or effective content that cannot be proven remains unresolved or unsupported.

## Compatibility

The existing Codex terminal behavior and `codex-scope.v0.1` JSON contract are unchanged. The compatibility command retains its additive `codex-scope.compatibility.v1` contract.

## Safety

The Gemini adapter does not invoke Gemini CLI, an LLM, runtime network access, hooks, extensions/plugins, or MCP servers. Inspection remains deterministic and read-only.
